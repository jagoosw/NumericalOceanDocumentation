NumericalOcean.GaussianInjection — Type

A release into the surface cells with a Gaussian footprint, as a forcing (in tracer units per second) on the tracer it is passed for, e.g. forcing = (; Alk2 = GaussianInjection(grid, (-49.5, 0), 5 * 365days)).

total_injection (tracer units × m³, e.g. 1000e12 mmol = 1 Tmol of alkalinity) is spread over the surface cells within cutoff (m) of center = (λ, φ) (degrees), weighted by exp(-r² / 2σ²) with σ in m, at a constant rate from start_time to start_time + duration (s of model time).

NumericalOcean.MaunaLoaCO₂ — Function
MaunaLoaCO₂(architecture = CPU();
            dataset = MaunaLoa(),
            name = :carbon_dioxide,
            start_date = DateTime(1958, 1, 1),
            end_date = DateTime(2018, 1, 1),
            dates = filter(date -> start_date ≤ date < end_date, all_dates(dataset, name)),
            dir = nothing,
            FT = Float64,
            period = forcing_period(MultiYearJRA55(), start_date, end_date))

Download the Scripps MaunaLoa record and return atmospheric CO₂ dry-air mole fraction (ppm) as a FieldTimeSeries located at (Nothing, Nothing, Nothing) — a single value per time, uniform in space — on a Flat, Flat, Flat grid. Sample it like any other FieldTimeSeries:

using Dates, Oceananigans

xCO₂ = MaunaLoaCO₂(arch; start_date = DateTime(1958, 3, 15))

xCO₂[1, 1, 1, Time(clock.time)] # ppm at the model's current time

start_date is the date model time zero represents — the simulation's own start date, not the record's, whenever the two differ.

The samples are placed at evenly spaced mid-month times (times is a range), starting half a month after the first day of the first selected month, rather than on the record's 15th-of-the-month dates. This keeps times a range on the GPU, so interpolating the series does not copy it to the host each time step; each sample is within ~2 days of its month's actual midpoint.

Time indexing is Cyclical. By default it takes the months from start_date to end_date and cycles them with the multi-year JRA55 forcing forced_ocean_simulation builds for the same dates (21915 days for 1958–2018, see forcing_period), so the CO₂ wraps back to 1958 with the atmosphere. The samples are spread evenly over the period, period / Nt apart (30.4375 days for 1958–2018), with the same spacing across the seam. Pass e.g. period = 365days with one year of dates to cycle in step with repeat-year forcing, or period = nothing for the mean Gregorian month (365.2425 / 12 days) spacing and a period of that times the number of samples.

Keyword Arguments

  • dataset: the MaunaLoa dataset, carrying the URL the CSV is fetched from.
  • name: which series to read — :carbon_dioxide (Mauna Loa, the default), :south_pole_carbon_dioxide, or :mean_carbon_dioxide.
  • start_date: the date corresponding to model time zero. Default: 1958-01-01, as forced_ocean_simulation.
  • end_date: the end of the forcing cycle. Default: 2018-01-01, as forced_ocean_simulation.
  • dates: the window of the record to use. Default: the months from start_date up to end_date.
  • dir: where the CSV is cached. Default: the NumericalEarth download cache.
  • FT: element type of the returned series. Default: Float64.
  • period: cycle length in seconds, or nothing for the span of dates plus one final mean month. Default: the multi-year JRA55 forcing's period from start_date to end_date.

Build a JRA55-forced ocean–sea-ice Simulation on grid, optionally carrying biogeochemistry with OAEMIP's initial conditions, rivers and iron dust. Extra passive tracers are added to (:T, :S).

Model time zero is start_date. The JRA55 forcing cycles every forcing_cycle seconds (see forcing_period: 21915 days for 1958–2018, 365 for repeat-year forcing) and the climatologies (WOA salinity, SeaWiFS chlorophyll, iron dust) every climatology_cycle (see climatology_period: 365.25 days, or 365), so all stay in phase with each other and the calendar from cycle to cycle, the climatologies to within 0.75 days. Cycle any atmosphere_tracers the same way, e.g. MaunaLoaCO₂(arch; dates, start_date, period = forcing_cycle).

Every progress_frequency iterations (nothing for never) the time, extrema of the state and wall time per step are logged, followed by a PROBE line of memory and GC use (unless ENV["OMIP_PROBE"] = "0"). Its reductions synchronise the GPU, so keep it infrequent.

NumericalOcean.pickup_restart! — Method
pickup_restart!(
    simulation,
    date;
    start_date,
    repeat_year,
    dir,
    prefix,
    restart_start_date,
    restart_end_date,
    cycle_length,
    cycle
) -> Any

Set simulation's model to the checkpoint of the OMIP spin-up closest to date, and its clock to that checkpoint's date as seconds since start_date (the start_date the simulation was built with).

With repeat_year = true (for RepeatYearJRA55 runs, with start_date = DateTime(1990, 1, 1)), the clock is instead set to the checkpoint's time of year since start_date, so e.g. pickup_restart!(simulation, DateTime(1990, 1, 1); start_date = DateTime(1990, 1, 1), repeat_year = true) starts from the spin-up's state closest to 1 Jan 1990 at the forcing's matching time of year.

The checkpoints are dir/prefix_iteration*.jld2, written by a run forced by MultiYearJRA55 from restart_start_date to restart_end_date, which it cycled every cycle_length seconds. The default, 21915 days + 3 hours for 1958–2018, is the period that run's forcing inferred for itself (see forcing_cycle_length); pass cycle_length = forcing_period(MultiYearJRA55(), restart_start_date, restart_end_date) (21915 days) for checkpoints from runs whose forcing is phase-locked by forced_ocean_simulation. A checkpoint's date is that of the atmospheric forcing it was last forced with. Only checkpoints from cycle (0-based, default: the last cycle present) are considered.

The new run's forcing is all phase-locked to the calendar, but in a checkpointed run with inferred periods only the 3-hourly JRA55 atmosphere and radiation sit at the dates assigned here: the rest drifted against them, so a state from its nth cycle was spun up under rivers n × 0.875 days behind where the new run puts them on the same date, WOA salinity restoring n × 15.125 days ahead and SeaWiFS chlorophyll n × 44.875 days behind, the climatologies a further day ahead for each 29 February (WOA) or behind for each 365-day year (SeaWiFS) since restart_start_date.

Only the model state is restored, and the iteration is set to zero, so the simulation initialises as a fresh run (output writer and callback schedules start from the new time, and the first step is forward Euler). Tracers and other state missing from the checkpoint (e.g. biogeochemical tracers when restarting from a physics-only spin-up) keep the values they were given when the simulation was built. simulation.stop_time is not changed: it is model time, so with repeat_year = false it must exceed the restored clock time.

Return the path of the checkpoint used.

NumericalOcean.InterpolatedIronDust — Type
InterpolatedIronDust(series; kwargs...)

OceanBioME's IronDustDeposition of the surface dust series (a 2D FieldTimeSeries on the model grid) as a forcing for Fe, with the time interpolation of series done once per update into a 2D field rather than in every cell of the Fe tendency kernel. kwargs are passed to IronDustDeposition.

Evaluated inline (IronDustDepositionForcing(series)), the time interpolation (a mod of the time, a search of times and two reads, in every thread) pushes the already heavy tracer tendency kernel over its register budget, slowing it ~10×. Here the kernel reads the surface dust from a 2D field; the vertical dissolution profile (znode and two exps) is still computed inline.

The surface dust is recomputed whenever the model's FieldTimeSeries are updated (every update_state!), so the forcing is the same as IronDustDepositionForcing(series; kwargs...).

NumericalOcean.MaunaLoa — Type
MaunaLoa(; url = MAUNA_LOA_URL)

The Scripps monthly mean atmospheric CO₂ record from Mauna Loa (:carbon_dioxide), with the South Pole (:south_pole_carbon_dioxide) and two-station mean (:mean_carbon_dioxide) series carried in the same file.

Values are dry-air mole fractions in ppm (µmol/mol) on the Scripps '12' calibration scale, seasonally detrended, and stamped at midnight on the 15th of each month. They are not partial pressures: no sea-level-pressure or water-vapour correction is applied.

The record runs from March 1958 to March 2024. Months the stations did not observe are filled from a seasonally detrended spline fit; the file's Flag column records which, and is ignored here.

url must be a raw URL serving the CSV itself — for pastebin, https://pastebin.com/raw/<id> rather than the page that wraps it.

See MaunaLoaCO₂ for the time series a simulation consumes.

NumericalOcean.JRA55DataStagingCallback — Method
JRA55DataStagingCallback(; source_dir, staging_dir, start_date, cycle_length = Inf, async = true)

Return a simulation callback that dynamically stages JRA55 yearly files from source_dir (slow disk) to staging_dir (fast scratch).

At each invocation the callback:

  1. Reaps any background staging tasks that have finished
  2. If the current year's data isn't ready yet, blocks until it is (safety fallback — should be rare if the callback fires often enough)
  3. Spawns background copies for the current and next year's files (if they aren't already on scratch or in flight)
  4. Removes files from two or more years ago to free space

Each year of JRA55 data is ~15–25 GB, so scratch holds at most ~50 GB at any time.

The year is that of the forcing at the model time, which cycles back to start_date every cycle_length seconds.

Async vs sync

With async = true (default), the callback returns immediately after Threads.@spawn, and the background task does the copy by launching an external cp process (run(cp …)), not Base.cp. This matters: the byte copy in Base.cp goes through a blocking sendfile ccall that is not gc-safe, so running it on a spawned thread parks that thread outside any safepoint and stalls the next stop-the-world GC — freezing the main loop for the entire copy. Shelling out keeps the byte-shuffling in a separate process and lets the Julia task wait on it cooperatively, so GC is never blocked. With Δt = 30 min, ~58 min of compute fits between year transitions, so a 20-min copy overlaps fully with compute.

The atomic mv(tmp, dst) inside atomic_replace! is the only point where concurrent readers can observe the file change. They see either the old symlink (slow read) or the new real copy (fast read), never a partial file. On MPI runs, the copy runs only on rank 0 in a background thread; cross-rank consistency comes from filesystem atomicity rather than an explicit barrier, so no MPI calls happen on the background thread.

Set async = false to fall back to the original blocking behaviour.

NumericalOcean.climatology_period — Method
climatology_period(forcing_period) -> Any

The period (seconds) to cycle an annual climatology with in a run whose forcing cycles every forcing_period seconds: the mean length of the years in the cycle (365.25 days for 1958–2018, 365 days for repeat-year forcing), so it repeats a whole number of times per forcing cycle and has the same phase in every cycle.

A 365-day climatology cannot follow leap days under Cyclical; at 365.25 days it stays within 0.75 days of the calendar. By itself it would cycle every 365 days (366 for a leap-year one, e.g. SeaWiFS 2000), running 15 days ahead of the calendar (45 days behind) by the end of 1958–2018 and starting each later cycle further out.

NumericalOcean.forcing_cycle_length — Method
forcing_cycle_length(
    dataset,
    start_date,
    end_date;
    name
) -> Any

The period (seconds) over which the JRA55 dataset forcing between start_date and end_date cycles, as its FieldTimeSeries infers it: the last node is included, so 1958–2018 cycles every 21915 days + 3 hours, not 21915 days. This is for the 3-hourly atmospheric state; the daily river fluxes cycle every 21916 days.

This is the cycle of runs built before forced_ocean_simulation set the period explicitly; later runs cycle every forcing_period (21915 days for 1958–2018).

NumericalOcean.forcing_period — Method
forcing_period(
    _::NumericalEarth.DataWrangling.JRA55.MultiYearJRA55,
    start_date,
    end_date
) -> Any

The period (seconds) over which forced_ocean_simulation cycles the JRA55 dataset: the calendar span from start_date to end_date for MultiYearJRA55 (21915 days for 1958–2018), one 365-day year for RepeatYearJRA55.

Left to infer it, a multi-year series cycles over its nodes plus one interval, and its nodes run to the first on or after end_date: from 1958 to 2018 that is 21915 days + 3 hours for the 3-hourly variables and 21916 days for the daily rivers and icebergs, so the rivers slip 0.875 days a cycle against the atmosphere and both slip against the calendar. With this period the node past end_date is only ever the far end of the last interval before the wrap.

NumericalOcean.setup_staging_directory — Method
setup_staging_directory(source_dir, staging_dir)

Populate staging_dir with symlinks to every .nc file in source_dir. Reads go through symlinks (slow) until files are staged with stage_jra55_year!. Also:

  • sweeps any leftover *.tmp from a killed prior run (half-written copies that would otherwise be mistaken for real copies);
  • replaces any real .nc file whose size doesn't match the source with a fresh symlink. A size mismatch means a prior run crashed mid-cp and left a truncated file — before this heal, HDF5 reads would fail with truncated file: eof = X, stored_eof = Y, and stage_jra55_year! would skip it (it only replaces symlinks).
